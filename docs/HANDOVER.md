## 5. 作業するときの必須ルール

### エージェントの報告を信用しない

**実運用で5件の誤りを検出しています。** すべて公開前に見つけました。

| 種類 | 例 |
| --- | --- |
| 製品名が実ページと違う | アリエール、食洗機用ジョイ（いずれもP&G） |
| 裏付けのない断定 | エステーの他社対応、アイリスオーヤマの「各社共通」 |
| 基準を満たすための水増し | 種類が確認できない漂白剤を社数合わせで採用 |

**必ず公式ページを1〜2件開いて、製品名・数値を突き合わせてください。**
特にP&Gなど、ブランドサイトの表記と流通名が違うメーカーは要注意です。

### 委譲するときは事実を要約して渡さない

仕様データを要約して執筆エージェントに渡した結果、**取りこぼした事実で記事が
根拠と矛盾しかけた**ことがあります（キッチンスポンジの抗菌表示）。

渡してよいのは**着眼点**だけです。プロンプトには必ず
「**私の指示と仕様データが食い違う場合は、必ず仕様データ側を正とする**」を入れてください。

### 検証が終わる前に執筆を走らせない

猫用トイレ消臭シートで、訂正が届く前に記事が書き上がり、**誤った内訳のまま完成**しました。
書き直しになりました。**仕様データの突き合わせを終えてから執筆を開始してください。**

### 散文で判定させず、機械可読のキーを持たせる

「対応するトイレ本体: 専用か他社対応かの明記は確認できず」という文字列を
「専用」と誤判定した事故がありました。**判断が分かれる項目は `対応区分` のような
独立したキー**にして、値を定型にしてください。消臭シートとドライシートで採用済みです。

### 複数エージェントに共有ファイルを同時編集させない

`src/pages/index.astro` と `public/sitemap.xml` は更新が失われます。
2本以上を並列で書かせるときは記事ファイルのみ担当させ、導線はまとめて追加してください。

### `git add -A` は使わない

`.claude/settings.json` で禁止しています。追加するパスを毎回明示してください。

## 6. 記事の型（これが媒体の価値）

7記事すべてに共通する構造があります。**読者が「同じだろう」と思っている箇所が、実は違う**という事実を、
メーカー公式表示だけで示すことです。

| 記事 | 崩している思い込み |
| --- | --- |
| 猫砂 | 同じライオンペットでも、鉱物系は流せず、おから系は流せる |
| 洗濯用漂白剤 | 「酸素系だから大丈夫」ではない。ウール・絹への可否が3通りに分かれる |
| 洗濯用漂白剤 | 同じワイドハイターでも、EXパワーとPRO抗菌は成分が違う（容量・使用量は同じ） |
| キッチンスポンジ | 抗菌加工の表示は2製品だけ。しかも適用範囲の書き方が違う |
| 犬用ペットシーツ | 「レギュラー」は共通規格ではない。短辺が31〜34cmに分かれる |
| 猫用トイレ消臭シート | 「システムトイレ用」でも、自分の本体で使えるかは判断できない |

**レビューを一切使わずに書いています。** 公式表示の差だけで「判断が分かれる箇所」を示すのが型です。
新しい記事もこの型を維持してください。

## 7. 絶対にやらないこと

- Amazonのページ・検索結果・画像CDN・レビューをスクレイピングする
- 購入者レビューを転載・要約する（アソシエイト運営規約違反）
- 実使用していない製品の使用感・実測値・体験談を書く（景表法のステマ規制）
- ASINを推測でURLに組み立てる（別商品に誘導する）
- 効果を保証する書き方をする（「必ず落ちる」「99.9%除菌できます」）
  - 公式に「99.9%抗菌」と表示があれば「その表示がある」と書くのは可
- 比較対象の製品リンクに検索結果を使う（関連消耗品は一般名なので可）
- 秘密値・収益額をコミットする（リポジトリは公開）
- **公開ゲートを通すためにポリシーを緩める**

最後の項目が最も重要です。基準を満たせないなら、記事を出さないのが正しい判断です。

## 10. Cloudflare Pages

| 項目 | 値 |
| --- | --- |
| Production branch | `main` |
| ビルドコマンド | `npm run build` |
| 出力ディレクトリ | `dist` |

`main` へ push すると本番ビルドが走ります。**CDNの反映に数分かかる**ため、
push直後に404や旧版が返ることがあります。数分待って再確認してください。

確認方法:

```bash
curl -sS -o /dev/null -w 'status=%{http_code}\n' -L 'https://erabi-note.jp/articles/<slug>/'
```
