# えらびノート 引き継ぎ書

最終更新: 2026-08-08

この文書は、一般商品比較メディア「えらびノート」の編集・実装・公開状況を次の担当者へ引き継ぐためのものです。**認証情報、APIキー、トークン、パスワード、秘密鍵はこのリポジトリや本書に保存しません。**

## 1. 媒体の概要

| 項目 | 内容 |
| --- | --- |
| 媒体名 | えらびノート |
| 公開URL | `https://erabi-note.jp/` |
| リポジトリ | `katoiek/product-guide-media` |
| フレームワーク | Astro（静的サイト） |
| ホスティング | Cloudflare Pages |
| Pagesプロジェクト | `product-guide-media` |
| 本番ブランチ | `main` |
| 目的 | 同じ購入目的を満たす、異なるメーカー／ブランドの具体的な製品を比較し、購入条件から選べるようにすること |

読者像は「欲しい商品ジャンルは決まっているが、複数メーカーのどの製品を選ぶべきか決められない人」です。

## 2. 編集方針と公開基準

### 比較記事の単位

- 比較対象は、同じ購入目的を持つ**異なるメーカー／ブランドの5〜7製品**。
- 同一メーカー・同一シリーズのサイズ、容量、色違いだけを並べた記事は作らない。
- 例: 「固まる猫砂を、鉱物系・紙系・おから系の異なるメーカー製品で比較する」は対象。
- 例: 「同一収納ボックスのサイズ違い比較」は対象外。

### 記事構成

1. 読者が迷う具体的な場面
2. 向かない人・事前に外す条件
3. ジャンル固有の選定基準（原則3つ程度）
4. 5〜7製品の比較表
5. 製品ごとの候補に残す条件・外す条件
6. 意見が割れやすい仕様と購入前の確認事項
7. 優先条件・使い方別の結論
8. Amazonの直接商品リンク（要件を満たす場合のみ）

### 根拠と表現

- 仕様、容量、素材、対応条件、注意事項はメーカー公式ページで確認する。
- 実使用していない商品について、体験談、実測値、使用感、レビューの要約は書かない。
- 価格、在庫、配送、販売条件は変動するため、記事中の固定比較の根拠にしない。
- 購入者レビュー、SNS投稿、動画、比較サイトは、比較軸の発見に限って利用する。転載・大量言い換え・保存はしない。
- 「必ず」「絶対」「誰にでも」などの断定や、健康効果・結果保証は書かない。

### 自動公開しない領域

以下は一般商品比較の自動公開対象外です。

- クレジットカード、ローン、保険、投資
- 転職、求人
- 医療、法律
- 健康効果をうたう商品

## 3. Amazonアソシエイトのルール

### 必須条件

商品ごとの読者向け購入導線には、メーカー公式ページではなくAmazonアソシエイトのリンクを使う。

公開できるAmazon商品データには、製品ごとに次が必要です。

- ASIN
- 商品名・メーカー／ブランド
- ASINと一致する直接商品URL
  - 形式例: `https://www.amazon.co.jp/dp/<ASIN>?tag=<associate-tag>`
- Amazonプログラムで利用が許可された商品画像URL
- 画像の利用許諾種別（`amazon_program_content` など）
- 取得・確認日

### 禁止・保留事項

- `https://www.amazon.co.jp/s?k=...` のような検索結果リンクは、商品リンクとして使わない。
- ASINを確認していないURLを推測で作らない。
- Amazonページ、検索結果、画像CDN、レビューをスクレイピングしない。
- メーカーサイトの製品写真は、明示的な掲載許可がない限り転載しない。
- 画像・ASIN・直接リンクがそろわない記事は、下書き・調査キューに置き、公開しない。

### 現在の状態

- サイト全体にはAmazonアソシエイトの識別文を掲載済み。
- Amazon Creators APIの認証は未設定。
- 猫砂記事で一度使われたAmazon検索リンクは削除済み。
- 現在は、正規のASIN直リンクと許諾済み画像が確認できるまで、猫砂記事に購入リンク・製品画像を掲載していない。

## 5. Cloudflare Pages と本番運用

### Git連携の設定

Cloudflare Pagesの設定値:

| 項目 | 値 |
| --- | --- |
| リポジトリ | `katoiek/product-guide-media` |
| Production branch | `main` |
| フレームワークプリセット | Astro |
| ビルドコマンド | `npm run build` |
| ビルド出力ディレクトリ | `dist` |
| ルートディレクトリ | 空欄 |

GitHubの`main`へpushするとCloudflare Pagesが本番ビルドする。新しいデプロイ行と固有の`*.product-guide-media.pages.dev` URLが発行されたことを確認してから、独自ドメインを確認する。

### 削除済みルート

`/contact/` は削除済み。`public/_redirects` で、次のルールによりHTTP 404を返す。

```text
/contact /404.html 404
/contact/ /404.html 404
```

`src/pages/404.astro` は削除済みURL用の404画面である。

### Cloudflare Web Analytics

Cloudflare Web Analyticsは有効化済み。`erabi-note.jp`上でCloudflare公式ビーコンと計測用設定の読み込みを確認済み。

## 6. 開発・検証手順

### ローカルビルド

```bash
npm install --no-audit --no-fund
npm run build
```

（旧引き継ぎ書にあった `/opt/data` 共有マウントでの `EPERM` 回避手順は、その環境が現存しないため削除した。）

### Git操作

`git add -A` は使わず、追加するパスを毎回明示する。削除したファイルが作業コピーに残らないよう、削除対象を明示してから commit する。push 前に `git status --short` で `.env` などの意図しないファイルが含まれていないことを確認する。

### 本番確認

削除・追加したルートは、トップページだけでなく直接確認する。

```bash
curl -sS -o /dev/null -w 'status=%{http_code}\n' -L \
  'https://erabi-note.jp/contact/'
```

期待値は`status=404`。

## 7. アフィリエイト処理の実装

**運用手順の詳細は [`docs/AUTOMATION.md`](./AUTOMATION.md) を参照する。** 本節は要点のみ。

以前の引き継ぎ書は、外部サンドボックス上の Python プロジェクト `/opt/data/affiliate_agent` を参照していた。
そのコードはリポジトリに含まれておらず再現できないため、**Node.js（サイトと同じスタック、依存追加なし）でリポジトリ内に作り直した**。

| パス | 役割 |
| --- | --- |
| `content/pipeline/policy.json` | 機械可読の公開ポリシー（唯一の正） |
| `content/pipeline/queue.json` | 企画キューと状態機械 |
| `content/pipeline/specs/<slug>.json` | メーカー公式仕様（記事の根拠） |
| `content/pipeline/products/<slug>.json` | ASIN・直接リンク・許諾済み画像 |
| `tools/amazon-fetch.mjs` | PA-API v5（SigV4署名）でのASIN・商品画像取得 |
| `tools/ingest-sitestripe.mjs` | PA-API未接続時のSiteStripe取り込み |
| `tools/validate-products.mjs` | ASIN直リンク・タグ一致・画像許諾の検証 |
| `tools/validate-article.mjs` | 記事の構成・表現・根拠・サイト内導線の検証 |
| `tools/gate.mjs` | 上記＋`astro build` をまとめた公開ゲート |
| `tools/queue.mjs` | キュー操作（status / next / set / add） |
| `.claude/agents/erabi-*.md` | 工程別エージェント5体 |
| `.claude/skills/erabi-pipeline/SKILL.md` | パイプラインのオーケストレータ |

Amazon商品正規化では、`/dp/<ASIN>`形式でASINと一致し、`tag`パラメータを持つURLだけを許可する。検索URLは拒否する。

検証は次で実行する。

```bash
npm install --no-audit --no-fund
npm run gate          # 商品 + 記事 + ビルド
npm run gate:fast     # ビルドを省略
```

## 8. 調査キューと自動公開の状態

キューの実体は `content/pipeline/queue.json`。現在の状態は `npm run queue status` で確認する。

- 猫砂記事（`assets_pending`）: 公開済みだが、仕様データに各製品の**メーカー公式ページURLが未記録**のため公開ゲートで落ちる。ASIN・画像も未取得で購入導線なし。
- 食洗機用洗剤、洗濯用液体洗剤、キッチンスポンジ（`spec_research`）: 前回の調査が外部接続エラーで中断し、仕様データ未取得。再実行時もメーカー公式ページだけを根拠にする。
- 定期実行ワークフロー `.github/workflows/pipeline.yml` は、`ANTHROPIC_API_KEY` が未設定の間スキップされる。未検証の商品・画像・Amazonリンクを含む記事は、ゲートで機械的に止まるため本番へ出ない。
- 新しい比較記事は、公式仕様の調査 → ASIN・直接リンク・画像の正規取得 → 公開ゲート通過 → ビルド確認 → GitHub push の順で処理する。

## 9. 現在の優先順位

1. Amazon Creators API、またはAmazon SiteStripeで、各製品のASIN・直接商品リンク・許諾済み商品画像を正規取得できる状態にする。
2. 猫砂比較の5製品について、商品名・ASIN・画像・特別リンクの一致を確認し、比較表へ製品写真と直接Amazonリンクを追加する。
3. 食洗機用洗剤、洗濯用液体洗剤、キッチンスポンジの各ジャンルで、異なる5〜7ブランドの公式仕様調査を完了する。
4. それぞれの商品アセットがそろった記事だけを公開する。
5. 公開後も仕様・購入条件の変更を確認し、根拠のない価格・性能・レビュー記述を追加しない。

## 10. 次担当者への注意

- 秘密値をチャット、Git、ログ、公開サイト、Markdownへ書かない。
- 製品写真を使う要求があっても、許諾不明のメーカー画像・検索結果画像を掲載しない。
- 「記事数を増やす」ことより、5〜7製品の根拠、直接Amazonリンク、画像許諾をそろえることを優先する。
- 公式仕様の確認先と、読者向けのAmazon購入リンクは役割が異なる。前者は根拠、後者は購入導線である。
- 公開ページに内部の自動化フロー、隔離キュー、レビュー収集方針などを詳細に掲載しない。
